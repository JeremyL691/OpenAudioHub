---
title: Email (SMTP) setup
description: Configure an SMTP server so OpenAudioHub can send email notifications.
---

Email notifications go out through any SMTP server you configure. That includes Postmark, Resend, Amazon SES, Mailgun, a Postfix server you run yourself, or any other SMTP service. This is an operator setting. Each user enables email in their own notification settings, described in [Notifications](/docs/guides/notifications).

## Configuration

Set these values in the environment that runs OpenAudioHub:

```bash
SMTP_HOST=smtp.example.com
SMTP_PORT=587                  # 465 when SMTP_SECURE=true, otherwise 587
SMTP_SECURE=false              # true for implicit TLS on port 465
SMTP_USER=apikey-or-username
SMTP_PASSWORD=secret
SMTP_FROM="OpenAudioHub <noreply@example.com>"
```

`SMTP_FROM` accepts a bare address, such as `noreply@example.com`, or a name with an address, such as `Name <user@example.com>`. Any other value is rejected at startup.

If `SMTP_FROM` is unset, the sender is `SMTP_USER`. If both are unset, the sender is `OpenAudioHub <noreply@host>`, where `host` is the host name in `APP_URL`.

Set `SMTP_REPLY_TO` to route replies to a monitored inbox while the sender stays a no-reply address.

The full list of SMTP settings and their defaults is in [Environment variables](./environment-variables).

## When SMTP is unset

When `SMTP_HOST` is unset, the email backend turns itself off. Sending a message does nothing and logs a "SMTP not configured" warning on the server. Users who enable email see no error in the interface, and no mail goes out.

## Verify the configuration

Any user can check the setup without waiting for a real event. Under **Settings → Notifications**, choose **Send test email**. That sends a message through your SMTP server, using the same path as real notifications, so a result here means real notifications will work too.
