---
title: S3-compatible storage
description: Store audio in AWS S3, Cloudflare R2, MinIO, Backblaze B2, or any S3-compatible service.
---

By default, OpenAudioHub stores audio on the local filesystem, in a Docker volume mounted at `/app/audio`. That needs no setup, works offline, and keeps everything under your control. Switch to S3-compatible storage when you want offsite durability, lower storage costs, or storage shared between instances.

OpenAudioHub works with any service that speaks the S3 protocol, including AWS S3, Cloudflare R2, MinIO, Backblaze B2, DigitalOcean Spaces, and Wasabi.

## Configure S3

Storage is configured once for the instance, in the environment, and every account uses the same backend. Set `DEFAULT_STORAGE_TYPE=s3` and the `S3_*` variables listed in [Environment variables](./environment-variables), then restart the stack.

The storage page in Settings shows the active backend and how much space your recordings use.

## Provider examples

### AWS S3

```bash
DEFAULT_STORAGE_TYPE=s3
S3_ENDPOINT=                  # leave blank
S3_BUCKET=your-bucket-name
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=YOUR_KEY
S3_SECRET_ACCESS_KEY=YOUR_SECRET
```

### Cloudflare R2

```bash
DEFAULT_STORAGE_TYPE=s3
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
S3_BUCKET=openaudiohub
S3_REGION=auto
S3_ACCESS_KEY_ID=YOUR_KEY
S3_SECRET_ACCESS_KEY=YOUR_SECRET
```

### MinIO (self-hosted)

```bash
DEFAULT_STORAGE_TYPE=s3
S3_ENDPOINT=http://minio:9000
S3_BUCKET=openaudiohub
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=YOUR_KEY
S3_SECRET_ACCESS_KEY=YOUR_SECRET
```

If MinIO runs on the same Docker network as OpenAudioHub, use the service name, as shown, rather than `localhost`.

### Backblaze B2

```bash
DEFAULT_STORAGE_TYPE=s3
S3_ENDPOINT=https://s3.<region>.backblazeb2.com
S3_BUCKET=your-bucket-name
S3_REGION=<region>
S3_ACCESS_KEY_ID=YOUR_KEY
S3_SECRET_ACCESS_KEY=YOUR_SECRET
```

### DigitalOcean Spaces

```bash
DEFAULT_STORAGE_TYPE=s3
S3_ENDPOINT=https://<region>.digitaloceanspaces.com
S3_BUCKET=your-space-name
S3_REGION=<region>
S3_ACCESS_KEY_ID=YOUR_KEY
S3_SECRET_ACCESS_KEY=YOUR_SECRET
```

## Encryption at the storage layer

OpenAudioHub's encryption at rest covers database fields, not audio objects. For S3, turn on server-side encryption at the bucket level, using SSE-S3, SSE-KMS, or your provider's equivalent. Per-object encryption inside the application is not implemented.

See [Encryption at rest](/docs/reference/encryption-at-rest) for the exact scope.

## Switching from local storage to S3

OpenAudioHub has no built-in tool that moves existing audio between backends. Because the backend is set for the whole instance, copy the audio before you switch:

1. Stop the OpenAudioHub container, so no new files are written during the copy.
2. Copy the local audio directory to the bucket with `aws s3 sync`, `rclone`, or a similar tool. Recording rows store the storage key, and the key layout is the same for every backend, so a straight copy is enough.
3. Set `DEFAULT_STORAGE_TYPE=s3` and the `S3_*` variables, then start the stack.
4. Open a few recordings and confirm that the audio plays.

Keep the local audio directory until you have confirmed the copy.
