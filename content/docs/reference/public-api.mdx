The `/api/v1/*` surface is OpenAudioHub's public, read-only API. Personal API keys authenticate it. Integrations such as Zapier, n8n, and your own scripts call it.

To create keys and configure webhooks, see [Automation API and webhooks](/docs/guides/automation-and-webhooks).

## Base URL

`https://<your-openaudiohub-host>/api/v1`

The host is the one you set as `APP_URL` in `.env`.

## Authentication

Send your personal API key as a Bearer token:

```http
Authorization: Bearer oah_...
```

Keys are 38 characters long: the prefix `oah_`, 30 random base62 characters, and a 4-character checksum. Keys created before version 1.0.0 use the `op_` prefix, and they are still accepted. Keys are read-only. A revoked or expired key returns `401 UNAUTHORIZED`.

## Rate limits

Every `/api/v1/*` request counts against two limits:

- **Per client IP:** 1,200 requests per minute.
- **Per authenticated identity:** 600 requests per minute, counted per API key or per signed-in session.

A limited request returns `429` with a JSON body, a `Retry-After` header, and these headers:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 17
X-RateLimit-Limit: 600
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1700000017
```

```json
{
  "error": "Rate limit exceeded",
  "code": "RATE_LIMITED",
  "details": { "retryAfter": 17, "limit": 600, "remaining": 0, "resetAt": 1700000017 }
}
```

If the instance is not behind a trusted proxy, the per-IP limit applies to a single shared bucket. Set `RATE_LIMIT_TRUST_PROXY_HEADERS` only behind a proxy that overwrites forwarding headers. See [Environment variables](/docs/self-hosting/environment-variables).

## Errors

Every error uses the same shape:

```json
{
  "error": "Human-readable message",
  "code": "MACHINE_READABLE_CODE",
  "details": { "field": "limit" }
}
```

Branch on `code`, not `error`. The text of `error` can change between releases. The codes you are most likely to handle:

| Code | HTTP | Meaning |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | The key is missing, malformed, revoked, or expired |
| `FORBIDDEN` | 403 | You are authenticated but not allowed |
| `ACCOUNT_SUSPENDED` | 403 | The account is suspended |
| `INVALID_INPUT` | 400 | A query parameter or field failed validation |
| `RECORDING_NOT_FOUND` | 404 | The recording does not exist, or is not yours |
| `NOT_FOUND` | 404 | The resource does not exist, for example a transcript that has not been produced yet |
| `RATE_LIMITED` | 429 | You hit one of the limits above |

## Endpoints

### List recordings

```http
GET /api/v1/recordings
```

All query parameters are optional:

| Parameter | Type | Notes |
| --- | --- | --- |
| `limit` | integer, 1 to 100 | Page size. Default 50. |
| `cursor` | string | The `next_cursor` value from the previous page |
| `created_since` | ISO timestamp | Recordings created at or after this time |
| `updated_since` | ISO timestamp | Recordings updated at or after this time |
| `has_transcription` | `true` or `false` | Filter by whether a transcript exists |

```bash
curl -H "Authorization: Bearer oah_..." \
  "https://your-host/api/v1/recordings?limit=20&has_transcription=true"
```

```js
const res = await fetch("https://your-host/api/v1/recordings?limit=20", {
  headers: { Authorization: `Bearer ${process.env.OPENAUDIOHUB_KEY}` },
});
const { data, next_cursor, has_more } = await res.json();
```

Response:

```json
{
  "data": [
    {
      "id": "...",
      "title": "Team standup",
      "created_at": "2026-05-13T12:00:00.000Z",
      "updated_at": "2026-05-13T12:00:00.000Z",
      "recorded_at": "2026-05-13T11:30:00.000Z",
      "duration_ms": 1820000,
      "filesize_bytes": 1234567,
      "device": { "serial_number": "...", "name": "Plaud Note", "model": "..." },
      "has_transcription": true,
      "has_summary": false,
      "links": {
        "self": "/api/v1/recordings/...",
        "transcript": "/api/v1/recordings/.../transcript",
        "audio": "/api/v1/recordings/.../audio"
      }
    }
  ],
  "next_cursor": "eyJ1cGRhdGVkQXQiOi...",
  "has_more": true
}
```

Pagination is cursor-based and sorted by `updated_at`, newest first. While `has_more` is `true`, pass `next_cursor` to the next request. When it is `false`, you have reached the end.

### Get a recording

```http
GET /api/v1/recordings/{id}
```

Returns the same shape as a list item, plus the `transcript` and `summary` objects when they exist. A recording that does not exist, or that belongs to someone else, returns `404 RECORDING_NOT_FOUND`.

### Get a transcript

```http
GET /api/v1/recordings/{id}/transcript
```

```json
{
  "language": "en",
  "text": "Full plaintext transcript...",
  "provider": "groq",
  "model": "whisper-large-v3",
  "created_at": "2026-05-13T12:01:23.000Z"
}
```

Returns `404 NOT_FOUND` when the recording exists but has no transcript yet. Listen for `transcription.completed` to know when to fetch it.

### Stream audio

```http
GET /api/v1/recordings/{id}/audio
```

Follow the redirect with `curl -L`. Range requests (RFC 7233) are supported:

```bash
curl -L -H "Authorization: Bearer oah_..." \
  -H "Range: bytes=0-65535" \
  -o head.mp3 \
  https://your-host/api/v1/recordings/01J.../audio
```

- For recordings on local storage, the response is the audio itself. `Content-Type` comes from the file extension, and the response is cacheable for five minutes. Range requests return `206` with `Content-Range`.
- For recordings in S3, the response is a `302` redirect to a pre-signed URL that expires after five minutes. Your client downloads the audio directly from S3, and OpenAudioHub does not proxy it.

A `416` response with `Content-Range: bytes */<size>` means the requested range is outside the file. Ends past the end of the file are trimmed to the last byte, as RFC 7233 requires.

## Writes

The `/api/v1/*` surface has no write endpoints. To add data, use the interface, or let sync bring recordings in from Plaud.

## Stability

The `/api/v1/*` surface is a versioned contract:

- Existing endpoints do not change in breaking ways. New fields are added, and existing fields keep their meaning.
- Error `code` values are stable. New codes can be added, and existing codes are not renamed.
- Removals and breaking changes go through a deprecation period, and the changelog records them.

If you need a new field or endpoint, open an issue so the design can be discussed before it ships.
