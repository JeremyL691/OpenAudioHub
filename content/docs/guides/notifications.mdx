---
title: Notifications
description: Bark push notifications, browser notifications, and email, with their setup.
---

OpenAudioHub can notify you when a sync finds new recordings or a transcription finishes. Three backends are included: Bark for iOS push, browser notifications, and email over SMTP. You can enable any combination.

Notifications never block sync. Each backend has a timeout, three seconds for Bark, and a similar limit for email. A notification that fails is logged and is not retried.

## Bark (iOS push)

[Bark](https://github.com/Finb/Bark) is a free iOS push service. Install the app, copy the personal push URL it gives you, and paste it under **Settings → Notifications**. The URL looks like `https://api.day.app/<your-key>`. It is stored for your account only.

Notifications are sent at the time-sensitive level, so they can break through Focus modes on iOS. If a notification you expected does not arrive, check the server logs.

## Browser notifications

Browser notifications use the standard Web Notifications API. They work in Chrome, Firefox, Safari, and Edge once you grant permission. Enable them under **Settings → Notifications**.

They appear only while an OpenAudioHub tab is open in a browser. For delivery while you are away, use Bark or email.

## Email

Email needs an SMTP server, which the operator configures. See [Email (SMTP) setup](/docs/self-hosting/email-smtp). Once it is configured, enable email under **Settings → Notifications**. OpenAudioHub then sends a message to your account address when a recording finishes syncing or a transcription completes.

To test the setup without waiting for an event, choose **Send test email**. If the operator has not configured SMTP, nothing is sent. The server logs a "SMTP not configured" warning, and the interface shows no error.

## Choosing a backend

| Need | Use |
| --- | --- |
| A push to your phone while you are away | Bark |
| A notice while OpenAudioHub is open | Browser |
| A persistent record of each sync result | Email |
