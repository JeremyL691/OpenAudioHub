---
title: AI providers
description: Configure transcription and summary providers, including OpenAI-compatible endpoints, Google Gemini, ElevenLabs, and local models.
---

OpenAudioHub works with several AI providers. Each provider has a base URL, an API key, and default models. You can add more than one, and choose a transcription provider and a summary provider for each recording.

## Adding a provider

Open **Settings → Providers** and choose **Add Provider**. Pick a preset, which fills in the base URL and suggests models. Paste your API key, choose a model, and save. Repeat for each provider you want to use.

## Presets

| Preset | Base URL | Notes |
| --- | --- | --- |
| OpenAI | `api.openai.com` (default) | `whisper-1` and `gpt-4o-transcribe` |
| Groq | `https://api.groq.com/openai/v1` | Fast Whisper transcription |
| Together AI | `https://api.together.xyz/v1` | Broad model selection |
| OpenRouter | `https://openrouter.ai/api/v1` | Audio-capable and chat models behind one key |
| SiliconFlow (China) | `https://api.siliconflow.cn/v1` | SenseVoice and other Chinese-market speech models, plus chat models for summaries |
| OpenCode Go | `https://opencode.ai/zen/go/v1` | Chat models for summaries and titles only. It does not transcribe audio |
| Google Gemini | Google's Gemini API | Native audio transcription |
| ElevenLabs | `https://api.elevenlabs.io/v1` | Scribe transcription with speaker labels |
| LM Studio | `http://localhost:1234/v1` | Runs on your own machine |
| Ollama | `http://localhost:11434/v1` | Runs on your own machine |
| Custom | The base URL your provider gives you | Any other OpenAI-compatible endpoint |

### Local model servers

LM Studio and Ollama default to `localhost`. Inside a container, `localhost` refers to the container, not the host. To reach a model server running on the Docker host, use `http://host.docker.internal:<port>` on macOS and Windows, or the Docker bridge address on Linux. If the model server runs in a container on the same Compose network, use its service name, for example `http://ollama:11434/v1`.

SiliconFlow (China) and OpenCode Go send their required headers themselves, so no proxy is needed. OpenCode Go is for summaries and titles. Choose a transcription provider separately.

## Transcription styles

- **OpenAI-style** sends audio to `/v1/audio/transcriptions`. OpenAI, Groq, Together AI, LM Studio, and Ollama use this style.
- **Chat-style** sends audio as a content part to `/v1/chat/completions`. OpenRouter uses this for models that accept audio input.
- **Gemini** uses Google's native `generateContent` API, because its OpenAI-compatible layer does not support audio transcription. Inline audio is limited to 20 MB. Larger files return a clear error.
- **ElevenLabs** uses its speech-to-text API, which can return speaker labels.

## Choosing models

Each preset comes with a list of known transcription models. To use a model that is not in the list, choose **Custom…** and type its name. Summaries accept any chat model. Choose a small, fast model unless you need a larger one.

Chat-only providers, such as OpenCode Go, list their chat models from the provider. Those lists leave out MiniMax and Qwen models, which use a different API format. SiliconFlow (China) keeps one default model per provider. If its default model is a transcription model, summaries use the preset's chat model, `Qwen/Qwen2.5-7B-Instruct`. Check that model is available on your account.

## Speaker labels

- **ElevenLabs Scribe:** turn on **Settings → Transcription → Speaker labels**. The optional "expected speakers" hint, from 1 to 32, can improve diarization. It is not a hard limit.
- **OpenAI `gpt-4o-transcribe-diarize`:** choose this model as the default, or for a single recording. The speaker labels toggle has no effect on it.

Other providers return a transcript without speaker labels.

Language is detected automatically by default. Change **Settings → Transcription → Default transcription language** only when auto-detection gets a recording wrong.

## What leaves your server

Audio sent for transcription, and transcript text sent for summaries, reach the provider in plaintext. Your provider can see them, and its policies apply. Encryption at rest protects the database. It does not protect these requests. To keep both on hardware you control, run a local provider on the same machine.

## Switching providers

On any recording, the workstation panel lets you pick a transcription provider and a summary provider. Changes apply right away. If a transcription is poor, run it again with a different provider.

## Automatic summaries

**Settings → Summary → Auto-generate summary after transcription** creates a summary after each successful transcription. That includes transcriptions you start by hand, automatic transcriptions after sync, and re-transcriptions. It is off by default, because each summary costs one extra provider call. You can choose a separate preset for automatic summaries, so meeting recordings can use "Meeting Notes" while manual summaries keep "General".

Automatic summaries use a built-in preset, not a custom prompt.

### Cost guardrails

- **Hourly cap.** Automatic summaries are limited per user by `AUTO_SUMMARY_RATE_LIMIT_PER_HOUR`, which defaults to 60. When the limit is reached, the transcript is still saved without a summary, and a `summary.failed` webhook reports a rate-limit error. The manual **Summarize** and **Re-generate** buttons are not limited.
- **Cheap fallback model.** If your default model is a transcription model, its id contains `whisper`. The summary call would fail against the audio endpoint, so OpenAudioHub uses a chat model that suits the provider instead:

| Provider base URL contains | Fallback chat model |
| --- | --- |
| `groq` | `llama-3.1-8b-instant` |
| `together` | `meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo` |
| `openrouter` | `openai/gpt-4o-mini` |
| Anything else | `gpt-4o-mini` |

Change the default model in **Settings → Providers** to use a different model.

### Re-transcription

Re-transcribing a recording deletes its old summary, because the summary describes the previous transcript. With automatic summaries on, a new summary is created. Otherwise, choose **Summarize** to create one.

### Failures

A failed summary does not affect the transcript. The transcript is saved, the `transcription.completed` webhook still fires, and `summary.failed` reports the error. You can retry the summary from the recording.
