---
title: Automation API and webhooks
description: Personal API keys, signed webhook deliveries, and the /api/v1 surface for external tools.
---

OpenAudioHub has a small, stable automation surface for external tools such as Zapier, n8n, and your own scripts. It has two parts:

- **Personal API keys** give read access to the `/api/v1/*` surface.
- **Webhooks** send events to a server you choose when something happens, such as a new recording or a finished transcription.

The full endpoint reference is in [Public API](/docs/reference/public-api).

## Personal API keys

Open **Settings → Integrations → API Keys** and create a key. Give it a name and, optionally, an expiry date. The key is shown once, so store it in a password manager or in the secret store of the tool that will use it.

A key starts with `oah_`, followed by 34 characters. Keys created before version 1.0.0 start with `op_`, and they keep working.

Send the key as a Bearer token:

```bash
curl -H "Authorization: Bearer oah_..." \
  https://your-openaudiohub-host/api/v1/recordings
```

Keys are read-only today. OpenAudioHub stores only an HMAC-SHA256 hash of each key, so a database leak does not expose usable keys. You can revoke a key at any time, and a revoked or expired key is rejected at once.

## Webhooks

Open **Settings → Integrations → Webhooks** and create an endpoint. Provide:

- **URL:** where OpenAudioHub sends events.
- **Events:** one or more of the event types below.
- **Description:** optional, for your own reference.

OpenAudioHub returns a signing secret that starts with `whsec_`. Copy it when it is shown. The secret is stored encrypted, and you use it to verify each delivery.

### Supported events

| Event | When it fires |
| --- | --- |
| `recording.synced` | A new recording finished syncing from Plaud |
| `recording.updated` | A recording's metadata changed |
| `recording.deleted` | A recording was deleted |
| `transcription.completed` | A transcription finished successfully |
| `transcription.failed` | A transcription failed after its retries |
| `summary.completed` | An automatic summary finished |
| `summary.failed` | An automatic summary failed. The transcript is kept. |

### Delivery format

Each delivery is a `POST` with a JSON body and these headers:

| Header | Meaning |
| --- | --- |
| `X-OpenAudioHub-Event` | The event name, such as `recording.synced` |
| `X-OpenAudioHub-Delivery` | A unique delivery ID. Use it to ignore duplicates. |
| `X-OpenAudioHub-Timestamp` | Unix time in seconds. It is also part of the signed payload. |
| `X-OpenAudioHub-Signature` | `t=<timestamp>,v1=<hex HMAC>`. See below. |

The User-Agent is `OpenAudioHub-Webhooks/1`.

The body includes the event name, the recording ID, and a recording payload in the same shape as `/api/v1/recordings/{id}`.

### Verifying signatures

The signed payload is the timestamp, a period, and the raw request body. The signature is the HMAC-SHA256 of that payload, using your `whsec_` secret. Reject a delivery when:

- The `t=` timestamp is more than five minutes from your server's clock. This blocks replays.
- The recomputed `v1` value does not match, using a constant-time comparison.

A Node.js receiver:

```js
import { createHmac, timingSafeEqual } from "node:crypto";

function verify(secret, header, rawBody, toleranceSeconds = 300) {
  const parts = new Map(
    header.split(",").map((p) => p.split("=")),
  );
  const t = Number(parts.get("t"));
  const sig = parts.get("v1");
  if (!Number.isFinite(t) || !sig) return false;
  if (Math.abs(Date.now() / 1000 - t) > toleranceSeconds) return false;

  const expected = createHmac("sha256", secret)
    .update(`${t}.${rawBody}`)
    .digest("hex");

  const a = Buffer.from(expected, "hex");
  const b = Buffer.from(sig, "hex");
  return a.length === b.length && timingSafeEqual(a, b);
}
```

The same algorithm is implemented in `src/lib/webhooks/signature.ts`.

### Allowed URLs

By default, a webhook URL can use `http://` or `https://`, and it can point at any host the OpenAudioHub container can reach. That includes Docker service names, such as `http://n8n:5678/webhook`, and private IP addresses. URLs with embedded credentials are rejected.

If your instance is reachable by other people, set `WEBHOOKS_REQUIRE_PUBLIC_TARGETS=true`. Then URLs must use HTTPS, must resolve to public addresses, and must not contain credentials. This stops your instance from being used to reach your private network. See [Environment variables](/docs/self-hosting/environment-variables).

### Retries

A non-2xx response or a network error schedules a retry. Retries wait 30 seconds, 2 minutes, 10 minutes, 1 hour, and 6 hours. After six failed attempts, the delivery is marked dead. Failed deliveries are recorded, and you can review them in **Settings → Integrations → Webhooks**.

## Write access

The `/api/v1/*` surface is read-only. It lists recordings, returns one recording, returns its transcript, and streams its audio. To add data, use the OpenAudioHub interface or sync from Plaud.
