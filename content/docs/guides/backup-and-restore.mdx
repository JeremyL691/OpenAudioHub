title: Backup and restore
description: Export your recordings, transcripts, and summaries, and recover an instance from an operations backup.

OpenAudioHub has three separate ways to export or back up data.

- **Full-data ZIP.** A portable copy of your content, from **Settings → Export/Backup**. Use it to take your data elsewhere or to keep an archive of it.
- **Transcript export.** A single file with the transcripts of all your recordings, in JSON, TXT, SRT, or VTT format.
- **Operations backup.** What an operator needs to recover an installation: the database, the audio and storage volumes, and the pipeline data. It is not a file you create from the interface.

## Full-data ZIP

Under **Settings → Export/Backup**, choose **Create full backup**. The job runs in the background. When it is ready, **Download** saves the ZIP.

The ZIP contains a `manifest.json` and one folder per recording. A folder holds the audio file, `transcript.txt`, `timeline.json`, and `summary.json`, for each item that exists. The manifest lists what each recording includes. If an audio file is missing or unreadable, the export fails, the partial ZIP is discarded, and you are not notified that it is ready. Check the manifest when you verify an archive.

The ZIP is plaintext, because OpenAudioHub decrypts your content before it writes the archive. Store it encrypted, do not send it by email, and keep it apart from your encryption key. The ZIP is not a server restore package, and it cannot be imported back into OpenAudioHub.

The file name is `openaudiohub-export-<id>.zip`.

## Transcript export

`GET /api/export?format=<format>` combines all of your recordings into one file. The supported formats are:

| Format | Content |
| --- | --- |
| `json` | One JSON document with every recording and its transcript |
| `txt` | Plain text, one block per recording |
| `srt` | SubRip subtitles for all recordings |
| `vtt` | WebVTT subtitles for all recordings |

## Operations backup and restore

An operations backup is for recovering an installation. It includes:

- A logical dump of the Postgres database.
- The audio and storage volumes, or your S3 bucket.
- The audio pipeline's SQLite database and work directory.
- The `ENCRYPTION_KEY`, stored separately from the rest.

Without the matching `ENCRYPTION_KEY`, the encrypted content in the database cannot be read. The [audio pipeline operations runbook](https://github.com/JeremyL691/OpenAudioHub/blob/main/docs/audio-pipeline-operations.md) describes how to capture a consistent backup, restore it into an isolated stack, and verify the result before you return it to service.

## What is encrypted

- **In the database,** sensitive fields are encrypted with AES-256-GCM. See [Encryption at rest](/docs/reference/encryption-at-rest).
- **In a ZIP from Settings → Export/Backup,** those fields are decrypted before they are written. Protect the file as plaintext personal data.
- **Audio in storage** is not encrypted by OpenAudioHub. Use server-side encryption on your bucket if you need it.
